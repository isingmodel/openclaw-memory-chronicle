# 부록 A. 근거 감사 지도

[← 이전: 용어집](14-glossary.md) · [목차](README.md)

이 책이 말하는 “현재”는 OpenClaw `main`의 [`a115af277410`](https://github.com/openclaw/openclaw/tree/a115af277410a91fb039d2ed699eafad706f5c73), 2026-07-18이다. 현재 동작, 출시된 동작, 과거 제안, 이 책의 권고는 같은 시제로 읽지 않는다.

## 정본 유지 원칙

- 역사·현재 구조·진화 동기를 바꿀 때는 해당 장을 먼저 갱신한다.
- 새 이정표나 출시 경계가 생기면 [12장](12-landmark-index.md)의 커밋·태그·동기 행을 함께 갱신한다.
- 근거, 재현 명령, 조사 한계가 달라지면 [13장](13-references-reproduction-and-conclusion.md)을 함께 갱신한다.
- 공개 제품 문서는 개별 계약과 사용법을 확인하는 근거다. 책과 다르면 양쪽이 가리키는 시점과 현재 소스·테스트를 확인한 뒤, 불일치 자체를 명시하고 영향을 받는 문서를 함께 바로잡는다.
- 합성 사례는 `예시`라고 표시하고, 실제 장애·사용자 보고·벤치마크 결과와 구분한다.

## 동기와 인과를 감사하는 순서

1. 커밋의 전체 변경, 소유 모듈, 호출자, 테스트를 읽어 **무엇이 어떻게 바뀌었는지** 먼저 확정한다.
2. 커밋 메시지와 연결된 PR·이슈·검토가 문제와 목표를 직접 밝히는지 확인한다. 연결이 확인되면 **명시적**, 없으면 코드가 허용하는 범위에서만 **코드에서 추론**이라고 적는다.
3. 비슷한 사용자 보고나 후속 사건이 있지만 해당 변경과 직접 연결되지 않으면 **맥락적·비인과**로 낮춘다. 압력의 존재와 특정 변경의 원인은 다른 주장이다.
4. 폴백을 감사할 때는 처음부터 설계된 복구 계약, 실제로 관측된 실패 사건, 코드에서 입증된 잠재 실패 경로를 나눈다.
5. **현재 계약**은 현재 시점의 상태를 입증할 뿐 과거 동기를 대신하지 않는다. `main`에 병합됨, 릴리스 태그에 포함됨, 설치에서 활성화됨도 각각 따로 확인한다.

[12장의 동기와 근거 색인](12-landmark-index.md#동기와-근거-색인)은 이 규칙을 41개 이정표에 적용한 빠른 감사표다. 각 행은 2장부터 7장의 서술과 직접 연결된 1차 링크를 압축한다.

## 불일치를 해결하는 순서

책의 주장과 다른 자료가 어긋나는 것처럼 보이면 먼저 양쪽이 말하는 “현재”가 언제인지 맞춘다. 다음으로 “커밋됨·`main` 병합됨·태그에 포함됨·설치되어 활성화됨”을 구분하고, 현재 소스와 테스트에서 실제 계약을 확인한다. 역사적 동기라면 연결된 PR·이슈·커밋 설명이 인과를 직접 밝히는지도 따로 확인한다.

그래도 불일치가 남으면 해당 장의 서술과 근거 표지를 먼저 바로잡고, 12장의 이정표와 13장의 참고문헌·재현법을 동기화한다. 공개 제품 문서의 계약 설명도 영향을 받는다면 같은 변경에서 맞춘다. 이렇게 해야 OpenClaw 저장소 안의 이 책이 하나의 정본으로 유지된다.
